# 0.8.4 本地退出与节点交接修复

## 触发路径

打开上层节点时，如果没有官方对话恰好结束于该节点，导航器会创建截至该轮的临时分支，再关闭自己的 App Server，将分支交给官方 Codex。恢复已归档的临时分支也经过这段交接流程。

旧流程只发送 SIGTERM 并等待 3 秒。发送信号前就丢掉了子进程引用并关闭输出读取；超时后既不能继续终止进程，也不能可靠重试。此时分支可能已经创建成功，但关闭失败会使整个打开操作报错。再次关闭还可能因为缺少进程引用而误报成功。

## 修复

- 先关闭标准输入，让 App Server 正常结束，同时继续读取输出，避免输出管道堵塞。
- 正常退出超过 3 秒后发送 SIGTERM，等待 2 秒；仍未退出则发送 SIGKILL，再等待 2 秒。信号只发送给当前客户端自己启动的子进程。
- 多次关闭共享同一等待结果，确认退出前保留进程引用。仍未退出时明确停止交接，保留后续清理重试能力。
- 新建客户端及打开官方侧栏均等待正在进行的清理；销毁插件后，不再由此前等待中的请求启动替代进程。

本次没有修改节点、父子关系、分支合并或根对话发现规则。

## 验证

Linux、Node 24.20.0，本机官方 Codex 扩展 26.1002.51308。

- 类型检查通过；21 个测试文件、108 项测试通过。
- 真实子进程测试覆盖正常退出、延迟退出、大量输出排空、SIGTERM 回退、忽略 SIGTERM 后 SIGKILL，以及关闭期间的并发请求处理。
- 桥接测试覆盖临时分支创建后的交接等待、清理失败后重试、启动失败后的清理和销毁期间禁止重启。
- 同一受控进程复现：0.8.3 使用缩短的 30 毫秒超时后报错，进程仍存活，同时第二次关闭误报成功；0.8.4 等待同一关闭流程，135.8 毫秒内完成清理，子进程确实退出。
- 使用真实 Codex App Server 做 3 次只读初始化、列表查询与退出检查，退出分别为 47.8、18.3、27.8 毫秒，均正常退出。

受控测试的超时缩短仅用于验证，不改变产品的 3/2/2 秒等待时间。真实 Codex 检查没有创建、归档或删除用户对话，也没有终止已有 App Server。此次未复现真实上层节点的偶发慢退出；验证的是已确认的退出处理缺陷及其修复。

## 本地试用

安装 0.8.4 后执行 VS Code 的 `Developer: Reload Window`，再打开此前容易报错的上层节点。清理需要回退时可能多等几秒；如进程最终仍无法退出，插件会停止交接并显示明确错误。

安装前已备份 0.8.3 扩展和导航器状态。本地安装验证完成后，经用户确认，将性能优化与退出交接修复一并更新至 GitHub。
